Context, alternatives, consequences, and who approved. These nine must be made before the platform hardens.

01

Shared capability distribution

Repository content, package, MCP tools, managed plugin marketplace, or hybrid. Spike scheduled against the Claude private marketplace.

In review
02

Claude-specific or provider-neutral

Gateway earns its keep only if attribution and budgets are required. Depends on provider policy.

In review
03

Catalog & control-plane implementation

Start GitHub-native and lightweight; adopt a portal product only when the need is proven.

Accepted
04

Secrets and machine identity

1Password as store of record, runtime injection from hosting secret stores.

Accepted
05

Observability content & retention

Metadata always; prompt and response content off until data classification is approved.

Blocked · needs data-policy owner
06

Production hosting & environments

Preserve Vercel where it fits; managed compute for scheduled and server workloads. No Kubernetes.

In review
07

Evaluation platform & release gates

Evals gate every core release. Platform selection follows the content-logging decision.

In review
08

Repository topology & ownership

One shared-core repository versus coordinated repositories. Owned with CODEOWNERS either way.

09

Platform posture

Assemble commodity layers, build only the CF-specific thin layer. End-to-end agent platforms and full scratch-build considered and set aside; reopening conditions recorded.
